## 开始前：沟通方式与网络自测

### 用用户听得懂的话推进

根据用户的提问和反馈判断其熟悉程度，不给用户贴“技术水平低”的标签。用户不熟悉构建、签名、文件路径等概念时，必须在**每一步**用简短、通俗的话说明：现在要做什么、为什么要做、当前有什么阻碍、下一步需要用户做什么，以及该步骤实际需要注意的事项。没有阻碍或不需要用户操作时直接说清楚，不制造问题，也不要堆砌整篇技术文档。

在即将进入依赖用户选择或材料的步骤前，及时预提问，不要等到操作失败才问。首次先问设备和已有材料，下载前说明文件大小与存放位置，安装前确认新装还是覆盖更新及存档备份，生成存档前解释新号与体验号区别。一次只问当前及紧接着下一步必需的少量问题；已明确的答案和授权直接复用，能自行检查的先检查。等待回答时继续不依赖该答案的工作。

例如：“我先检查下载速度，因为构建工具包比较大，避免下载到一半才发现网络不通。你现在不用操作；接下来请告诉我电脑还有多少可用空间，或者允许我直接检查。”网络受阻时则说明具体影响和替代方案，而不是只抛出报错或说“请自行解决”。

### 先测试实际下载环境，不假定有可靠代理

默认用户的 Agent **没有可靠的网络代理**。在下载大文件之前，先用可用工具做一次有超时、有流量上限的快速检查。即使已能阅读仓库，也不能据此认定 Release 大附件能顺畅下载；Agent 云端的网络结果也不代表用户电脑的网络。

1. 在实际负责下载文件的环境中，检查仓库/Release 页面或 GitHub API 的连通性，记录响应状态和耗时。单次连接超时可设约 10 秒、请求总时限约 20 秒；失败时有限重试，不无休止等待。
2. 从实际 Release 元数据中取得一个真实附件 URL，跟随重定向测试文件下载。优先读取约 1–4 MiB 的小段数据，设置约 20 秒总时限和硬性读取量上限，记录实际字节数、平均速度及是否中断。服务器忽略 Range 时也要主动停止，不能把测速变成整包下载。仅做 HEAD 请求不能证明下载速度。
3. 结合实际附件大小估算下载耗时。例如，连续超时、连接反复中断，或大包测速持续低于约 200 KiB/s，应视为质量不佳的信号；这些是判断参考，不是固定通过门槛。只有鉴权失败、API 限流或链接失效时，应区分错误原因，不能全部归因于网络。
4. 不能执行网络请求时，如实说明未能自测；提供用户可以执行的短步骤或命令，并解释需要返回什么结果，不虚构测试成功。

如果连接质量不佳，**必须明确告诉用户“当前环境到 GitHub 的网络连接质量较差”**，附上实际测得的超时、速度或预计等待时间。这可能发生在中国大陆部分网络下，但不能仅凭用户所在地区推断。同步说明构建仍缺哪些下载、其他准备工作能否继续。

随后由你主动制定并尝试可行的 Release 获取方案，不能只让用户“自己找代理”。根据自身工具和用户环境自行选择：可用的官方附件直链、支持续传的下载工具、用户已有且允许使用的代理/其他网络、浏览器下载后交给 Agent，或在获准且网络可用的另一环境下载后传回。需要用户配合时，用人话说明该方案、为什么可行、用户只需完成哪一步。

本文不指定永久有效的加速站或代理地址。第三方中转若确有需要，应先核实可用性并告知用户来源；不向其发送 GitHub 凭据、签名密钥或存档，不关闭 TLS 证书校验。取得文件后对照官方提供的 SHA-256 校验；暂时无法取得官方校验值时明确标记未验证，不宣称文件可信。代理安装、系统设置变更和付费服务按用户授权处理，不以解决下载为由擅自更改环境。

## 1. 本仓库能帮用户做什么

本项目是在电脑上运行的离线存档编辑器，用于配套 Android/NS 离线版本的 `account.json`。可以从模板新建存档，或打开已有存档、预览修改、保存并导回游戏。它不提供游戏客户端，也不处理官方在线账号。

先阅读 [README](../README.md)、[源码说明](README.md)及目标平台的 [Android 使用方式](使用方式-Android.md)或 [NS 使用方式](使用方式-NS.md)。**仅使用编辑器，不需要用户提供 1.9/2.4 APK 或 7.x 资源。** 用户还没有游戏时，转到对应游戏指南；只有进入游戏构建任务才索要那些材料。

最终交付是用户需要的存档文件、原档备份位置，以及针对其平台的导回步骤，不是只给一个编辑器下载链接。

## 2. 开始前先问清楚

先检查已有信息，再按步骤询问：用户要新建还是修改旧档；使用 Android 还是 NS、哪个离线构建；电脑系统；需要改哪些数值或进度；已有存档在哪。新手不必理解 JSON，直接解释“这是保存角色和进度的文件”。

修改旧档时，明确索要**实际游玩后导出的** `account.json`，不要误用安装包附带的初始档。接受本地路径、上传或可访问的共享位置；给出已确认电脑上的具体存放文件夹。用户不知道怎么导出时，按第 6 节带其操作。新建模板无需先索要旧档。

编辑前结束游戏及正在写存档的服务端，将文件复制到电脑，并保留一份独立原档。MTP/FTP 中的文件先复制到本地再打开，避免直接编辑传输中的文件。

## 3. 获取并启动编辑器

按前面的网络自测流程检查 [本项目 Releases](https://github.com/ClearwSea/BH-LOCRENASCI-ACT-EDIT/releases)，读取当前正式发布说明，下载适合 Windows 的附件；按附件提供的官方校验值验证并完整解压。选择该包内实际的存档编辑器 EXE，不猜带版本号的文件名。发布包通常不要求用户另装 Python，以当前发布说明为准。

已有可用源码环境时，也可以在仓库根目录运行：

```powershell
python save_editor.py
```

源码运行依赖 Python 标准库和 Tcl/Tk；本文编写时文档建议带 Tcl/Tk 的 Windows Python 3.13。检查当前环境能否导入 `tkinter`，不要将聊天环境的 Python 等同于用户电脑的 GUI 环境。缺少 Python/Tk 时先说明，再按授权安装或改用发布包。

## 4. 从模板生成存档

先用人话解释两种选择，再让用户选择：

| 模板 | 适合谁 | 需要说明 |
| --- | --- | --- |
| 新号 | 想从头体验 | 从低等级、初始角色与装备开始，不自动拥有体验号的进度 |
| 满级体验号 | 想体验角色、装备和关卡 | 已有高等级及预设进度；装备范围以模板说明为准，不代表全部内容经过实战验证 |

在顶部选择模板，点击“使用模板新建”，检查预览后保存到**不存在的新文件名**。建议交付文件使用 `account.json`；若目录中已有同名档，先另选位置，不覆盖唯一旧档。

“首次登录”开场选项仅对满足条件的新号使用。Android 必须先确认目标构建支持；本文编写时仅舰长 1 级可勾选，默认关闭，修改等级会取消。**NS 完整开场流程尚未验证，保留关闭**，除非当前项目文档已有新的明确验收结论。

模板昵称与签名在编辑器里只读，普通存档可编辑；游戏内修改按客户端行为处理。不要擅自解锁这些字段或修改模板来绕过限制。

## 5. 修改已有存档

点击“打开存档”，选择电脑上的副本，只修改用户要求的项目。点击“预览修改”，用简单的话说明变化及影响，再按已明确的意图保存或另存。

| 修改项 | 本文编写时的行为，执行前核对当前说明 |
| --- | --- |
| 舰长等级 | 范围 1–80；改级会清零当前等级经验，不联动升级角色/装备，不补发升级奖励 |
| 金币、水晶、体力、友情点 | 按工具校验范围修改，不绕过输入校验 |
| 普通存档昵称、签名 | 可编辑；模板身份字段仍受只读限制 |
| 剧情/外传全部通关 | 补齐所支持的普通剧情/外传记录及星级，相关任务按已领取处理，不补发奖励；不等于困难、噩梦和所有玩法全通 |
| 樱色轮回 | 从所选轮回开头继续；跳过不会直接发奖，回到旧剧情重玩可能再次获得剧情奖励，既有结算领取记录保留 |
| 深渊到达 32 关、段位 | 32 关表示可挑战，不表示已打完；需要有效当期状态，先在游戏刷新本期深渊并结束战斗，再退出导出 |

不勾选进度项表示不修改，并非清空；不要为了某一项操作顺手重置其他内容。深渊改段位保留现有楼层、道具及领奖记录，不补发升段奖励，但会清除旧段位交互及最终层计时，进入后刷新温度和对手。

工具会检查原文件是否被外部修改，已有档保存会生成原文件备份，另存目标和新模板目标不能覆盖已有文件。遇到冲突时先检查游戏是否仍运行、是否拿错文件，不删除校验来强行保存。指出实际备份文件位置；把编辑器自动备份与用户独立原档一起保留。

## 6. 按平台导回

### Android

优先使用该游戏构建启动页提供的“导出当前存档”与“选择存档/重选存档”。先导出当前进度，再在电脑修改；导回时选择修改后的 `account.json`，确认是否替换及保留旧档。具体流程见 [Android 游戏指南](https://github.com/ClearwSea/BH2017-LOCRENASCI/blob/main/docs/agent-guide.md)。

旧版独立服务端或其他分支先按 [Android 使用方式](使用方式-Android.md)确认实际存档路径。应用私有目录通常无法通过普通 USB 文件传输访问，不要求新手直接进入 `/data/user/0/`。电脑运行的服务端应替换其实际使用的存档，不要误放到手机。仅在具备对应权限和授权时使用 ADB 等工具。

### NS

先 HOME → X **完全关闭游戏**，仅回到 HOME 不够。用用户已有可用的 DBI、FTP 或直连 SD 卡方式复制文件。默认路径为：

```text
sd:/switch/bh3_2017/server-stage3/data/account.json
```

核对当前构建是否改过路径，编辑完成后以 `account.json` 名称放回原位置。DBI 中操作的是 SD 卡文件，不是系统存档导入；MTP 文件先复制到电脑。部署环境见 [NS 游戏指南](https://github.com/ClearwSea/BH-NX-Ferculum/blob/main/docs/agent-guide.md)。不要将 Android 导入方式或“首次登录”支持结论直接套到 NS。

### 验证与恢复

重新启动游戏，核对所改数值或进度，完成一次正常保存并重启检查持久性。文件保存成功不等于游戏已验收。失败时保留错误和修改档，完全关闭游戏/服务端，再将原档备份恢复到实际读取位置；不通过卸载或删除全部数据排错。

配套离线版登录账号密码可随意填写，这不代表支持官方在线账号，也不能保证任意第三方分支采用同样行为。

## 7. 开发与打包（仅需要时）

直接运行源码不需要游戏客户端或原工程。修改编辑器后在仓库根目录运行：

```powershell
python -B -m unittest test_save_editor
```

需要生成 EXE 时，核对 [源码说明](README.md)和 `requirements-build.txt`，按授权准备依赖：

```powershell
python -m venv .build-env
.\.build-env\Scripts\python.exe -m pip install -r requirements-build.txt
.\build_exe.cmd
```

输出为 `dist/BH3-V1.9-Save-Editor.exe`。`templates/` 和 `stage_catalog.json` 随源码提供；原工程的模板生成脚本及私有输入不在本仓库，不要假定可重新生成全部模板。构建依赖下载也要先核验实际网络，不能将 GitHub 通畅等同于包源通畅。

## 8. 排错与交付

打不开文件时检查是否完整 JSON、是否为兼容离线档；找不到字段时核对版本与模板，不随意补造字段。无法保存时检查目标路径、权限、文件是否被修改和目标是否已存在。游戏中数值不变时检查是否导回了实际运行位置、游戏是否覆盖了编辑结果。

收集具体报错、编辑器版本、目标游戏平台/版本和最少复现步骤；需要样例时征得用户同意并去除个人信息，不默认上传真实存档。发 Issue 需用户明确要求。

交付时说明：生成/修改了什么、输出存档和原档备份在哪里、如何导回、哪些项目已验证。没有游戏实测就明确写“文件已保存，游戏内待验证”。
